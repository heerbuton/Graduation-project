## 1. 项目全景规划与当前定位

本项目致力于实现从“古琴减字谱扫描件”到“现代可读乐谱（简谱/五线谱/MEI）”或指法语义的端到端自动翻译系统。整体架构拆分为四大核心模块：

1. **视觉感知层 (CV/YOLO)**：从扫描件中检测并精准提取散落的减字谱细粒度原子部件（本阶段核心攻坚，目前已推进至 V07 终极特训期与 2.5 倍物理放大对抗微调期）。
2. **空间拓扑与序列化层 (规则/GNN)**：将散落的检测框按减字谱语法进行空间组装（如上下、半包围），重组完整语义单元生成结构化 JSON。
3. **语义推理层 (LLM)**：结合上下文翻译古籍专有术语，完成消歧、定音、节奏推断。
4. **编码与渲染层 (Web/UI)**：映射至 MEI XML 并在 Web 端渲染对照显示（面向最终用户的可视化呈现与交互）。

## 2. 核心硬性约束与工程规范（防崩红线）

在实操过程中，结合硬件条件与框架底层逻辑，项目确立了以下不可触碰的工程红线，以确保实验的可复现性与系统稳定性：

- **硬件防 OOM 限制**：由于受限于 NVIDIA RTX 3060 Laptop (6GB VRAM) 的物理显存，在训练高分辨率图像时，`batch` 需严格控制在 4 到 16 之间，严防显存溢出引发训练中断。当遭遇极长周期训练导致“显存碎片化 (CUDA Memory Fragmentation)”崩溃时，必须通过 `resume=True` 重启全新 Python 进程以释放并重置 VRAM 空间，实现无缝断点续训。
- **环境稳定规约 (Windows)**：
  - 为避免 DataLoader 多进程触发 `WinError 1455`（页面文件太小）及 `0xC0000005`（内存访问越界），**所有训练过程与导出评估脚本强制 `workers=0`**，宁可牺牲部分 I/O 速度也要换取绝对稳定。
  - 训练中途评估或导出 per-class 指标时，**强制使用 `device="cpu"`**，绝对严禁与正在训练的 GPU 并发抢占显存。
- **数据与输出规范**：
  - 目标类别（Classes）严格固定为 **66 类**（包含数字、勾、抹、挑、大指等），无论是否存在 0 样本类（如抹挑、半轮等），**绝对严禁修改类别 ID 与顺序**。
  - 导出 `per-class` 验证指标时，必须使用 `metrics.box.ap_class_index` 进行精确对齐映射，杜绝“验证实例数为 0 但 Recall 非 0”的错位脏数据。
  - **路径编码规约**：Windows 环境下，由于 OpenCV `cv2.imwrite` 及 YAML 解析极易触发 GBK 乱码（如“长锁”变为“闀块攣”），必须强制使用 `yaml.safe_load(encoding='utf-8')`，并采用 `cv2.imdecode/imencode` 配合 `numpy.fromfile` 的方式处理包含中文的高维路径。
  - 代码变量/文件名强制全英文；输出落盘产物（CSV）强制使用中文列名与 `utf-8-sig` 编码，确保数据后处理兼容性。

## 3. 数据集工程演进史与实验动机 (Data Pipeline Evolution)

针对减字谱“目标极小、排版密集、类别极端长尾（不平衡）”的特性，本项目的数据集构建绝非一蹴而就。为了彻底解决密集微小目标检测和极端少样本问题，项目基于严格的“训练-诊断-迭代”闭环，经历了七个核心大版本的演进：

### 3.1 `v01`：数字活字盘建立期（高精度种子库）

- **动机与目的**：人工全图标注成本高昂且难以保证像素级精度，因此需要先建立一个高质量的“数字活字盘”种子集，以驱动后续的自动化合成数据引擎。
- **具体策略**：从 100+ 页原始扫描件中抽取 10–20 页作为“素材矿”，不强求全页标注。采用 1–2 像素误差的紧致包围盒标注，收集 66 类原子部件，每类目标收集 20–50 个高质量变体。随后，利用灰度化、Otsu 二值化、形态学去噪流程，将墨迹与纸张分离，写入 alpha 通道导出透明 PNG 素材（Clean 数据）。
- **结果与结论**：成功沉淀了高度纯净的部件素材库，为彻底根除人工标注带来的“不精准”和“背景噪声”奠定了物理基础。

### 3.2 `v02_blank`：整页基线期（极具排雷价值的废弃方案）

- **动机与目的**：作为目标检测的最初阶段，旨在建立最原始的基准线（Baseline）。测试 YOLO 网络是否具备直接处理 912×1440 高分辨率整页扫描件的能力，以及在全局视野下对微小原子部件的检测下限。
- **具体策略**：直接输入白底黑字的完整扫描件进行训练。
- **实验结果与缺陷**：彻底失败。早期训练 P/R/mAP 接近 0，EarlyStopping 正常触发，最终验证小目标/数字类 Recall 极低甚至为 0。
- **深度诊断与结论**：由于整页图中存在大量极其密集的字符，且前期标注并未实现 100% 的全覆盖，导致大量“未被标注的微小真实部件”被 YOLO 训练机制错误地当做了“背景（Background）”进行吸收。这种严重的**负样本污染**（背景污染）直接摧毁了模型的特征映射，压制了所有小目标的学习，导致召回率几乎为 0。

### 3.3 `v03_patches`：网格切片期（确立长尾全景基准）

- **动机与目的**：为了根除 `v02` 中致命的“未标注目标当背景”污染问题，同时放大目标在输入图像中的相对像素占比。通过缩小视野，强迫模型只关注局部的有效特征，提高有效监督密度。
- **具体策略**：弃用整页输入，改用固定步长（如 384）对原图进行 640×640 的滑动窗口裁剪，或使用脚本以每个 GT bbox 的中心点作为裁剪中心生成 Patch 样本。引入物理红线 `KEEP_FULLY_INSIDE=True`。
- **实验结果与瓶颈**：实验成功建立了有效的基础检测能力。但随之暴露了极其严重的**极端长尾/少样本（Few-Shot）**瓶颈。核心关注类在整个训练集中仅能切出 20~30 个实例，导致数字类与“勾/抹/挑”的 Recall 依然普遍为 0。

### 3.4 `v04_patches`：目标驱动抖动期（失败的探索与反思，极具学术排雷价值）

- **动机与目的**：直接针对 `v03` 暴露出的长尾 Few-Shot 瓶颈发起总攻。试图通过平移过采样（Jitter）强行扩充罕见目标数量。
- **具体策略**：锁定“关注类”，以稀缺目标为中心加入随机 $(x,y)$ 抖动连续裁剪扩充 8 次。
- **实验结果与深度诊断**：遭遇了经典的**“未标注假阴性中毒 (Unlabeled False Negative Poisoning)”**。由于减字谱排版紧凑，抖动平移必定截断相邻字符。模型在吸收了海量“带有特征墨迹但被标记为背景”的毒药数据后，演化出服务端极端保守策略：“只要目标不处于视野正中央，就绝对不预测”，导致关键类 Recall 暴跌归零。

### 3.5 `v05_copypaste`：精准拼贴与混合数据流期（特征净化与激活期）

- **动机与目的**：在诊断出大模型面对极端长尾分布时会发生“容量反噬”后，确立必须回归 Data-Centric AI。将算力与增强策略 100% 倾注于拯救剩余的极度稀缺指法类。避免边缘截断中毒，转向最纯净的实例级离线粘贴增强（Copy-Paste）。
- **具体策略**：建库提纯、均匀组装，构建 `data_hybrid.yaml`，将真实切片、Number 数据集与指法特训补丁包三剑合璧。
- **实验结果与目的**：150 轮特训后彻底验证了 Data-Centric 策略的成功。模型整体 Precision 极高，稀缺指法类终于打破 0 的封锁线。但网络对真实密集的古籍排版依然表现出极高的置信度保守性。

### 3.6 `v06_hardcore`：上下文感知拼贴与对抗微调期（抗干扰与破除尺度固化）

- **动机与目的**：`v05` 成功打通了稀缺类的特征映射，但在实际全页推理中遭遇了“跨字巨框”的尺度塌陷与严重漏检。为打破尺度固化与上下文缺失，开展地狱级对抗特训。
- **具体策略**：印章库剥离、Context-Aware Copy-Paste（正片叠底，融入真实古籍底布）、打破尺度固化（引入 0.7x~1.3x 尺度抖动，微调放开 `scale=0.3` 和 `translate=0.1`）。

### 3.7 `v07_ultimate_real` 与 `V07_Hybrid` 终极缝合期（局部特写与等比物理放大）

- **动机与目的**：在筹备最终全量微调时，对原切片引擎进行严格数据审计，发现了一个隐蔽的**“一口吞”物理尺度塌陷 Bug**：34 张真实古籍全页扫描件（平均物理尺寸仅为 324×562）在使用 `640x640` 的大窗口进行滑动切割时，几乎无法产生滑动截取，且彻底失去了放大效果，导致输入模型的依然是微小且密集的字符群。
- **具体策略（动态窗口与同步放大机制）**：
  1. **智能 Padding 防形变**：针对窄边（如宽度极小的古籍页），强制在右侧或底部进行灰色 (114) 像素 Padding，确保物理裁剪框不溢出、特征不拉伸畸变。
  2. **小窗截取 + 同步等比放大**：依据数据统计中位数，将滑动物理窗口（`crop_size`）缩减至 `256x256`（步长 128 以保证 50% 重叠率）。在原图上切下 `256x256` 局部特写后，强制 `cv2.resize` 到 `640x640`。
  3. **坐标映射**：内部减字坐标同步乘以 2.5 倍（640/256）的 `Scale Factor`，实现真正的“高清微距大特写”。该策略将 34 张原图扩增为 268 张高纯度特写切片，继承了 16201 个完美放大的目标框。
- **终极三源数据融合策略 (Hybrid Pipeline)**：为了彻底粉碎历史训练遗留的混乱目录结构，编写了底层穿透清洗脚本：
  - 无视原有的 `train/val/test` 结构，使用 `rglob` 递归提取所有有效图片与标签。
  - **分而治之，独立洗牌**：对 V07 真实放大特写、Number海量数字集分别进行内部乱序，严格按 8:2 切分 `Train/Val`。
  - **红线拦截**：对 V06（带有正片叠底干扰的合成特训图）强制 100% 灌入 `Train` 集合。严防合成数据污染验证集，死守模型真实泛化能力的评估底线。
  - **序列化统一**：融合输出全局序列化命名（如 `v07_real_train_00001.jpg`），最终建立 6803 张训练集与 949 张绝对纯净验证集的终极大一统 `V07_Hybrid` 库。

## 4. 模型训练与核心战役复盘

在特征保护与模型容量的博弈中，本项目沉淀了以下关键训练策略与学术发现：

### 4.1 核心特征保护策略（致命陷阱规避超参调优）

YOLO 默认的增强参数对古籍减字谱具有毁灭性破坏。现已固化以下定制针对性超参：

- **`imgsz=768` / `640`**：基于物理切片与放大的标准尺寸。
- **`mosaic=0.0`**：**致命陷阱规避**。强行关闭马赛克拼接，防止目标被二次缩放碎化。
- **`scale=0.1`**（仅适用于基础特征培养阶段）：严格限制随机缩放幅度，保护脆弱的小目标特征不被扭曲。
- **`fliplr=0.0`**：关闭水平翻转，严格保护古汉字左右结构的语义特征。
- **`patience=0`**：禁用早停机制，强迫模型在长尾数据流中持续迭代至预定轮次。

### 4.2 算力破局的受挫与深度剖析：大模型在长尾分布下的“容量反噬”

- **异常现象**：将参数量极少的 `yolo11n` 升级至容量更大的 `yolo11s` (9M 参数) 进行 150 轮训练后，Loss 暴降，但最终验证时微小目标的成绩劣于小模型。大数量类别 Recall 极高。
- **深度诊断（梯度淹没与过拟合捷径）**：参数量巨大的模型在面对极度不平衡的数据时，极其聪明地采取了“走捷径”策略。稀少样本产生的微弱梯度瞬间被庞大类别的梯度淹没。大模型将庞大参数全部用于死记硬背大样本类别，对微小样本直接放弃。
- **核心启示**：在绝对样本量极端的长尾场景下，单纯堆砌模型容量反而会遭到反噬。必须回归 Data-Centric AI 从数据层面开刀。

### 4.3 评估决策指标转换

放弃单纯紧盯 `mAP` 或 `best.pt` 的自动更新，转向使用**关注类（一~十、勾、抹、挑、大指）的 per-class Recall** 作为下一轮权重选型（best vs last）的绝对标尺。

### 4.4 战果验收与推理期尺度塌陷排雷 (Scale Collapse)

- **整页推理的灾难**：在直接使用全视野推理时，模型出现严重的“跨字巨无霸框”。
- **SAHI 切片推理与物理拦截**：必须采用 **Sliding Window Inference (滑动切片推理)**。引入物理逻辑拦截（如 `MAX_VALID_WIDTH/HEIGHT`），强行物理斩断大尺寸幻觉框。
- **Batched NMS 解决重叠压制**：“大指”包围“一”、“勾”包含横线是物理常态。弃用全局类别无关 NMS，全面转用 `batched_nms` (按类别独立结算)，确保不同类别的嵌套指法被完美同时提取，免于被吞噬。

### 4.5 V07 终极微调工程实践 (API调用与状态对齐)

- 彻底摒弃纯命令行执行，转为封装 `train_v07_finetune.py` 的 Ultralytics API 范式。
- 脚本内部硬编码封锁了 `workers=0`、`batch=16` 等防崩溃红线。
- 引入 `resume` 状态开关以应对 Windows 底层的显存碎片化突发崩溃。
- 通过在 API 参数中强行指定 `project="runs_yolo11"` 和 `name="y11_v07_hybrid_s_finetuned"`，实现了训练产物输出路径与此前 V05 的绝对对其与连贯性。
