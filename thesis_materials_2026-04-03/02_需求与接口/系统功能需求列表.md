# 系统功能需求列表（论文版）

## 1. 用户端功能需求（FR-U）

1. `FR-U01` 图片上传：用户可上传古琴减字谱图片（支持拖拽或点击选择）。
2. `FR-U02` 一键打谱：点击“开始打谱”后，系统自动执行完整流水线。
3. `FR-U03` 分阶段可视化：可查看“特征提取、拓扑序列、乐理推理、打谱渲染”四个阶段结果。
4. `FR-U04` 交互校对：在识别结果图上悬停查看字段，并对关键字段进行编辑（Right Hand、Left Hand、Left Finger、Hui、Xian）。
5. `FR-U05` 软删除控制：支持对错误组进行标记删除（不进入后续推理）。
6. `FR-U06` 局部重跑：应用修正后仅重跑后续链路（不重复整图识别），提升迭代效率。
7. `FR-U07` Demo 快速验证：支持加载预置样例进行流程演示。
8. `FR-U08` 结果预览：支持查看 LLM 结构化结果与最终渲染谱面。
9. `FR-U09` MusicXML 获取：前端可获取后端返回的 MusicXML 文本（用于导出或下游对接）。
10. `FR-U10` 异常提示：上传失败、解析失败、重跑失败时提供清晰错误信息。

## 2. 系统端功能需求（FR-S）

1. `FR-S01` 图像文件存储：接收上传文件并持久化到静态目录。
2. `FR-S02` YOLO 检测：输出检测框、类别、置信度等基础识别结果。
3. `FR-S03` 拓扑构建：将检测框聚合为 `group_x`，提取语义字段并生成 `topology_json`。
4. `FR-S04` 序列生成：按固定顺序生成 `jianzi_sequence` 供 LLM 使用。
5. `FR-S05` LLM 推理：依据拓扑序列推断音高、八度、时值、技法等字段。
6. `FR-S06` 结果规范化：将 LLM 输出标准化为可渲染的 `score_model`。
7. `FR-S07` MusicXML 编码：将推理结果编码为 MusicXML 文本。
8. `FR-S08` 拓扑修正重跑：接收前端修订后的 `topology_json` 并执行后续链路重算。
9. `FR-S09` 测试样例接口：提供固定样例全流程接口，便于回归验证。
10. `FR-S10` 可观测输出：各阶段关键中间结果可落盘为 JSON 供追溯。

## 3. 非功能需求（NFR）

1. `NFR01` 可解释性：中间结果可视化，支持“图像证据 -> 字段结果”追溯。
2. `NFR02` 可维护性：模块化分层（CV/拓扑/LLM/XML）便于独立替换与调优。
3. `NFR03` 稳定性：对异常输入和 LLM 非法输出提供修复与报错机制。
4. `NFR04` 交互效率：支持“局部修正 + 后续重跑”减少重复计算时间。
5. `NFR05` 扩展性：可扩展模型权重、阈值参数与规则策略。

## 4. 论文写作建议

- 将 `FR-U` 对应“用户价值”，`FR-S` 对应“系统能力”，`NFR` 对应“工程质量”。
- 每类至少配 1 张示意图（见 `03_图表与截图规划/UI截图清单与作用说明.md`）。
